# Фронтенд «Цифровой механик»

Веб-клиент механика: выбор машины и проверки, запрос результата у ML-сервиса, вердикт на понятном языке и диалог с помощником.

Как запустить и какие переменные окружения нужны — в [README в корне репозитория](../README.md).

## Эвристики

Заказчик не задаёт точных формул, поэтому значения выбраны командой. Они лежат в `src/config/heuristics.ts`; правила их применения — в `src/features/diagnosis/assessment.ts`.

| Что определяем | Правило |
|---|---|
| Низкая уверенность модели | `confidence < 0.55` или `confidence` не указан |
| Слабое отклонение | `anomaly_score < 0.65` |
| Умеренное отклонение | `0.65 ≤ anomaly_score < 0.85` |
| Сильное отклонение | `anomaly_score ≥ 0.85` |

Когда оценка отклонения и уверенность расходятся, решает уверенность: ниже порога результат считается недостоверным при любой оценке отклонения, даже высокой.

Порог уверенности и шкала отклонения показаны механику в вердикте, в разделе «Показатели проверки». Текст строится из тех же констант, поэтому интерфейс и конфиг не расходятся.

Приоритет заявки (FR-08) появится вместе с заявкой. Сила отклонения — одно из его оснований; остальные — уверенность модели, тип неисправности и критичность узла по руководству.

## Как строится вердикт

Вид вердикта зависит только от полей `status`, `signal_quality` и `confidence`. Правила проверяются сверху вниз, срабатывает первое подходящее.

| Условие | Вердикт | Что показываем |
|---|---|---|
| `status = check_failed` или `signal_quality = bad` | Анализ не выполнен | Причину и просьбу повторить запись. Вывода о двигателе, названия неисправности, оценки отклонения и уверенности нет |
| Низкая уверенность | Результат недостоверен | Уверенность и порог, что заметил сервис, просьбу повторить проверку. Гипотез, проверок и действий нет |
| `status = normal` | Норма | «Значимых отклонений не обнаружено», без рекомендаций по ремонту |
| `status = anomaly` | Обнаружено отклонение | Наблюдения → гипотеза → что проверить → возможные действия → источник → ограничения |

При `signal_quality = bad` анализ считается несостоявшимся, даже если сервис прислал `status = anomaly`: признаки неисправности из такого ответа не показываются.

При `signal_quality = warning` вердикт остаётся прежним, к нему добавляется предупреждение: запись с помехами, достоверность может быть ниже.

Что ещё важно:

- Вердикт называет группу неисправностей по названию. Код вида `F08` механику не показывается.
- Порядок проверки и допустимые значения в вердикте не приводятся: источника для них пока нет. Механика отправляем к руководству по ремонту его двигателя.
- Поле `description` — внешний текст. Он выводится цитатой с подписью «Описание от сервиса диагностики» и на вид вердикта не влияет, что бы в нём ни было написано.

Логика вердикта — в `src/features/diagnosis/verdict.ts`, отображение — в `DiagnosisVerdict.tsx`.

## Диалог с помощником

Диалог относится к одной проверке одной машины. Когда механик выбирает другую машину или проверку, диалог начинается заново: ответы по одному двигателю не остаются на экране рядом с другим.

В ленту попадают:

- результат диагностики — вердиктом от помощника;
- вопросы механика и ответы на них;
- ошибки: сервис диагностики недоступен, помощник не ответил.

Сообщение отправляется клавишей Enter или кнопкой «Отправить». Shift+Enter переносит строку. Диалог хранится только в памяти страницы и пропадает при перезагрузке.

### Помощник пока не подключён

ИИ-агент ещё в разработке, поэтому на вопросы отвечает заглушка. Она сообщает, что помощник не подключён, и никуда ничего не отправляет.

Всё обращение к агенту собрано в одной функции — `askAgent` в `src/features/chat/agent.ts`. Она получает текст вопроса, машину, проверку и последний результат диагностики. Чтобы подключить агента, достаточно заменить её тело на вызов клиента из `src/api/`; лента и поле ввода не меняются.

Адрес агента в репозитории не хранится. При подключении он задаётся в `.env`, как адреса остальных сервисов.

### Голосовой ввод

Кнопка с микрофоном рядом с полем ввода включает распознавание речи. Распознанная фраза дописывается в поле и сама не отправляется: механик читает текст, правит его и отправляет сам.

| Условие | Что видит механик |
|---|---|
| Браузер умеет распознавать речь, страница открыта по `https://` или с `localhost` | Кнопку с микрофоном |
| Браузер не умеет распознавать речь (например, Firefox) | Кнопки нет, под полем пояснение |
| Страница открыта по `http://` не с `localhost` | Кнопки нет, под полем пояснение про защищённый адрес |

Распознавание выполняет браузер (Web Speech API), язык — русский. В Chrome и Edge запись голоса при этом уходит на сервис распознавания разработчика браузера, поэтому нужен доступ в интернет. Если распознать не удалось, под полем появляется причина: нет доступа к микрофону, речь не расслышана, микрофон не найден, сервис недоступен.

## Проверки для демонстрации

| Случай | Машина | Проверка |
|---|---|---|
| Отклонение | `M333YK47` | `S-0005` |
| Отклонение, запись с помехами | `P854BT78` | `S-0021` |
| Сильное отклонение | `B418HK98` | `S-0009` |
| Норма | `M333YK47` | `S-0004` |
| Анализ не выполнен | `P456AT178` | `S-0003` |
| Низкая уверенность | `M739BA198` | `S-0103` |

В данных mock-сервиса `signal_quality = bad` встречается только вместе с `check_failed`. Случай «запись непригодна, но статус `anomaly` или `normal`» проверялся на подменённых ответах сервиса.

## Переход на рабочий ML-сервис

Адрес ML-сервиса задаётся одной переменной `VITE_MOCK_ML_URL` в `.env`. Чтобы перейти с mock-сервиса на рабочий, поменяйте её значение и пересоберите приложение; код менять не нужно.

Если приложение открыто по `https://`, сервисы тоже должны отвечать по `https://`: запросы со страницы HTTPS на адрес `http://` браузер блокирует.
