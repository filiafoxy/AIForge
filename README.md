# Цифровой механик (НейроДВС)

Хакатон «ИИкузница» (26–27.11.2026). Проект — веб-приложение для диагностики транспортных средств по результатам проверок: просмотр парка, получение диагноза от ML-сервиса и оформление заявок в ТОиР.

## Структура репозитория

| Путь | Назначение |
|---|---|
| `frontend/` | Веб-клиент: React, Vite, TypeScript |
| `.cursor/rules/` | Правила совместной работы агентов в репозитории |

Материалы технического задания, описания кейса и локальный mock-сервер **не публикуются** в открытом репозитории и хранятся только локально (см. `.gitignore`).

Исключение — два файла данных mock-сервера, `vehicles.json` и `fault_types.json`. Их копии лежат в `frontend/src/data/`: сервис не отдаёт список машин, и без этих файлов фронтенд не собирается.

## Роли в репозитории

- Фронтенд разрабатывается в `frontend/`.
- Исходные ТЗ и mock API подключаются локально из рабочей копии (каталоги `docs/` и `neurodvs_mock/` у разработчика).

## Запуск фронтенда

Нужен Node.js версии 20.19 и выше или 22.12 и выше.

```bash
cd frontend
cp .env.example .env
npm install
npm run dev
```

В командной строке Windows вместо `cp` используйте `copy`.

Приложение откроется по адресу `http://localhost:5173`. Адрес `http://127.0.0.1:5173` не сработает: сервер разработки слушает только `localhost`.

Адреса сервисов задаются в `frontend/.env`:

| Переменная | Сервис | Значение в `.env.example` |
|---|---|---|
| `VITE_MOCK_ML_URL` | Mock ML, `POST /diagnose` | `http://127.0.0.1:8001` |
| `VITE_MOCK_TOIR_URL` | Mock ТОиР, `POST /tickets` | `http://127.0.0.1:8002` |
| `VITE_AGENT_URL` | ИИ-агент, полный адрес вебхука | пусто — адрес выдаёт команда агента |

Список машин и проверок работает без сервисов. Результат диагностики механику сообщает ИИ-агент, поэтому для него нужны и Mock ML, и адрес агента в `VITE_AGENT_URL`. Пока адрес не задан, приложение показывает предупреждение.

Для локальной разработки используйте адреса из `.env.example` (`127.0.0.1`). Адреса корпоративных стендов в личном `.env` доступны только по VPN.

Запуск mock-сервисов, демонстрационные сценарии С1–С3 и сборка для стенда по HTTPS описаны в [`frontend/README.md`](frontend/README.md).

Проверки перед коммитом:

```bash
npm run typecheck
npm run build
```

## Статус

Готово во фронтенде:

- каркас приложения и чтение адресов сервисов из `.env`;
- выбор машины (с поиском по госномеру) и проверки;
- по кнопке диагностики приложение запрашивает у ИИ-агента заключение по результату проверки; результат ML-сервиса агент получает сам;
- запрос результата у Mock ML с обработкой ошибок: по нему приложение решает, предлагать ли заявку, а приоритет заявки берётся из ответа помощника (запасной расчёт — в приложении);
- вопросы помощнику с изображениями (`multipart/form-data`, поле `files`);
- диалог с помощником: заключение, ответы и ошибки в ленте сообщений, текстовый и голосовой ввод;
- вопросы механика уходят ИИ-агенту, его ответы показываются в ленте;
- заявка на дефектовку: форма, заполненная по черновику агента, предпросмотр, отправка в ТОиР только после подтверждения, номер заявки в ленте;
- история созданных заявок, которая хранится в браузере и переживает перезагрузку;
- вёрстка от 320px, предупреждения об отсутствии сети и об адресах сервисов, которые браузер заблокирует на странице HTTPS.

Порог уверенности, шкала отклонения, расчёт приоритета заявки, условия для заявки, устройство диалога, формат обмена с агентом и состав заявки описаны в `frontend/README.md`.

Дальше по плану: проверка заключений и черновиков заявки на настоящем агенте.
